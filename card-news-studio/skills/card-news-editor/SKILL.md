# 카드뉴스 편집 기준

이 프로젝트의 독자와 목적을 먼저 읽고 카드의 흐름을 정한다. 첫 카드는 독자가 겪는 장면이나 얻을 내용을 분명히 하고, 중간 카드는 근거와 설명을 이어 주며, 마지막 카드는 자료가 뒷받침하는 실천 또는 요점을 남긴다. 특정 장수나 문구를 모든 주제에 강제하지 않는다.

자료에 없는 숫자·기관명·연구 결과·날짜를 권위 있는 근거처럼 보충하지 않는다. 각 카드의 핵심 주장을 뒷받침하는 source_ids를 연결한다. source_ids가 있다는 것만으로 주장이 정확한 것은 아니므로 실제 자료 문장과 대조한다. 확인이 필요한 사실은 단정하지 않고, 자료가 부족하면 필요한 정보를 요청하거나 현재 자료로 가능한 범위를 좁힌다.

카드 하나에는 읽는 사람이 기억할 핵심 하나를 둔다. 제목은 본문의 내용을 예고하며 같은 말을 크게 반복하는 장식 문구로 만들지 않는다. 화면에 넘치는 글을 해결할 때는 글자 크기를 계속 줄이기보다 의미를 보존하며 문장을 나누거나 카드를 재구성한다. 과장된 약속과 클릭을 유도하는 불확실한 수치를 피한다.

부분 수정 요청에서는 지정된 카드의 ID와 수정 목적을 확인한다. 다른 카드의 사실·순서·표현을 함께 바꾸지 않는다. 수정 때문에 인접 카드와 연결이 끊어지면 그 이유와 필요한 추가 변경을 사용자에게 설명한다. 애플리케이션에서 선택 카드만 반영하는 경우 그 출력 계약을 따른다.

출력 키와 자료 구조는 호출자가 제공한 schema를 따른다. Markdown 코드 펜스나 해설을 JSON 앞뒤에 붙이지 않는다. 실제 이미지 렌더링은 별도 도구·프로그램의 역할이며, 원고 생성만으로 이미지가 완성됐다고 하지 않는다.

세부 편집 판단은 [편집 사례](references/editorial-decisions.md)를 참고한다. 앱이 이 파일을 명시적으로 읽어 요청에 넣는 방식과, 호스트가 Skill을 자동 발견하는 방식은 구별한다. 이 지침은 실행 권한을 부여하지 않는다.
