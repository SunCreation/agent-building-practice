# 실제 검증 범위

검증일: 2026-09-08. 이 문서는 설치·실행 경로와 실제 모델 성능을 구분합니다.

## 설치와 실행

- macOS 26.5.2 / Apple Silicon / Python 3.13.13에서 `uv sync --locked`를 실행했습니다.
- `uv run run.py`와 `--help`가 정상 종료하며, 내부 cli.py를 직접 실행하면 올바른 실행 위치와 명령을 안내합니다.
- Python 패키지 설치에 Harbor나 Docker를 요구하지 않습니다. 원본 채점용 pytest·mypy·flake8는 잠금 파일에 포함됩니다.
- 빈 캐시에서 고정 upstream 118개 파일 다운로드·SHA256 검사에 성공했습니다.
- 원본 task.toml의 easy 2 / medium 4 / hard 4와 목록이 일치합니다.

## 구현 회귀 검사

새 ZIP을 별도 폴더에 풀어 `uv sync --locked`와 `uv run python -m pytest -q`를 실행했습니다. **77개 테스트가 통과**했습니다. 프로세스 시간·출력 제한, 경로 거절, 세션 기록, 원본 파일 해시·준비, 별도 채점과 점수 집계를 검사합니다. 잘못된 두 진입 방식 `uv run harness_lab/cli.py`와 내부 폴더의 `uv run cli.py`도 친절한 실행 안내로 종료하는 것을 확인했습니다.

## 원본과 달라진 실행 조건

- 절대 경로를 시행별 workspace 아래로 변경합니다. Bash 설치 스크립트를 실행하지 않고 이미 설치한 Python과 pytest로 검사합니다. 하위 Python/mypy/flake8 호출도 현재 Python 환경에 맞춥니다.
- 데이터 복구 문제의 원본 Docker COPY에는 기대 정답 파일이 포함되어 있습니다. 로컬 이식판은 이 파일을 모델 작업 폴더에서 제외하고 채점기만 원본 캐시에서 읽게 합니다. 원본과의 의도적인 차이입니다.
- 원본의 컨테이너 이미지·CPU·메모리 제한을 재현하지 않습니다. Python 실행 시간과 출력 상한은 있지만 OS 보안 샌드박스가 아닙니다.
- 원본 검사도 완전하지 않습니다. 예를 들어 바둑 문제의 타입·형식 검사는 오류 출력을 표시해도 그 반환코드만으로 실패시키지 않습니다. 점수로 제품의 모든 요구 충족을 증명하지 않습니다.
- 데이터 복구 준비의 원본 난수는 유지합니다. 실행마다 생성 파일 해시를 기록하므로, 같은 upstream 커밋이 모든 생성 바이트까지 같다는 뜻은 아닙니다.
- Windows와 Linux를 고려한 Python 실행 경로를 사용하지만, 이번 배포의 실제 원본 10문제 실행 검증은 macOS에서 수행했습니다. 다른 OS 전체 통과를 주장하지 않습니다.

## 실행 중 발견한 하네스 개선

- 모델에 전달한 원문은 로컬 절대경로를 포함하지만 평가 도구가 상대경로만 받아 반복 오류가 발생했습니다. 평가 백엔드가 승인된 workspace 내부 절대경로를 상대경로로 변환하도록 수정했습니다. 일반 LocalTools의 정책은 바꾸지 않았고 외부 경로·상위 이동·심볼릭 링크 거절 회귀 검사를 추가했습니다.
- 기존 이벤트 기록만으로는 도구 입력·결과를 분석하기 어려워 시행별 `agent/sessions/trial.json`에 실제 모델 대화를 저장합니다. 출력 제한 적용 후 기록이며 원본 프로세스 출력 전체는 아닙니다.
