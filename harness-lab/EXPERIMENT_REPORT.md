# 하네스 구현과 실험 보고서
빈칸은 실행 후 채웁니다. 아래는 결과 예시가 아니라 제출 양식입니다.

## 제품과 구현
- 사용자 시나리오 / 완성한 PRD 위치:
- 구현 언어와 실행 방법:
- 직접 작성하거나 변경한 부분 / 참고한 부분:
- 모델·도구 반복, 오류·종료, 권한, 세션의 코드 위치:
- Python 예시와 다른 설계 결정 및 이유:

## 평가 조건
- 원본 commit / subset ID / manifest SHA256:
- 제공자와 모델의 실제 이름:
- 코드 commit 또는 소스 SHA256 (기준 / 개선):
- 실행 환경 / 아키텍처 / Python 버전 / 로컬 이식판 버전:
- 의존성 잠금 파일, 로컬 실행 조건과 재현 제약:
- 문항 수 10 / easy 2 / medium 4 / hard 4 / 문항당 반복 수:
- 모델 호출·도구·시간·출력 한도:
- 기준 실행 폴더 / 개선 실행 폴더:
- 설치·문제 준비·채점 경로 확인 결과 (개발 진단은 학생 점수에서 제외):

|---|---|---|---|---|---|---|---|---|---|
| 기준 | 미측정 | | | | | | | | | |
| 개선 | 미측정 | | | | | | | | | |

관측하지 않은 시간·토큰·비용은 '알 수 없음'으로 씁니다. 별도 가격표로 비용을 계산했다면 공식 청구값과 구별하고 단가·날짜·계산 방법을 적습니다.

## 실패 분석과 개선 가설
- 대표 실패의 요청 / 관찰한 도구 실행 / 채점 결과:
- 추정 원인과 이를 뒷받침하는 기록:
- 변경한 한 가지 요소:
- 예상한 영향:
- 실제 변화 (좋아진 문제와 나빠진 문제 모두):
- 동일하게 유지한 조건 / 바뀐 조건:
- 결론과 다음 실험:

점수가 내려가거나 그대로여도 결과를 기록합니다. 이 10문항에서의 차이를 전체 성능 우월성으로 일반화하지 않습니다. 같은 문항을 반복 개선에 사용한 개발 실험이라는 한계를 설명합니다.

## 제출 확인
- [ ] 실행 가능한 소스와 잠금 파일, 실행 안내
- [ ] PRD·결정 기록·인터페이스·완료 조건
- [ ] 기준/개선의 설정, run-metadata.json, 원본 trial result와 실행 기록
- [ ] 두 실행의 10문항 결과 CSV·JSON·HTML
- [ ] 개선 가설, 구현 변경과 관찰 결과
- [ ] 키·토큰·개인 자료 제외

## 로컬 이식과 검증 범위

- 난이도 출처: 고정 upstream task.toml (easy 2 / medium 4 / hard 4)
- 실행 방식: local-port, Docker 미사용
- OS·CPU·메모리와 동시 실행 프로그램:
- 원본 대비 변경: 작업 경로, 현재 Python 실행 파일, 설치 보일러플레이트 제외, 기대값 파일의 평가자 전용 이동
- 채점기 제약 또는 원본 검사 오류가 결과에 미친 영향:
- 다른 운영체제에서 실제 실행했는지:

공식 컨테이너 점수나 전체 벤치마크 점수로 표현하지 않습니다. 기준·개선의 소스 사본과 환경 조건을 함께 제출합니다.
