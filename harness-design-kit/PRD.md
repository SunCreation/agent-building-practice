# 개인 에이전트 하네스 PRD
상태: 설계 대화 전. OPEN을 AI가 임의로 채우지 않는다.

## 제공된 제품 목표
사용자가 자연어로 작업을 요청하면 모델이 필요한 도구를 선택하고, 내 프로그램이 이를 검사·실행하여 결과를 다시 모델에 전달한다. 자료를 읽는 범용 작업과 코드를 수정하고 검증하는 코딩 작업을 모두 다룬다. 사용자는 진행 상황과 실패 이유를 확인할 수 있다.
PRD(Product Requirements Document)는 무엇을 누구를 위해 만들고 어떤 결과를 완료로 볼지 기록한다. 구현 방법의 모든 세부사항을 미리 고정하는 문서는 아니다.

## 공통 요구사항
| ID | 제품이 해야 할 일 | 학생이 구체화할 부분 |
|---|---|---|
| R01 | 작업 요청을 받고 진행·완료·실패를 구분한다 | 사용자 입력/UI, 작업 식별과 상태 표시 |
| R02 | 모델→도구 요청→검사→실행→결과 반환을 직접 구현한다 | 반복 횟수·시간 제한과 오류 정책 |

| R04 | 코드 변경을 보여 주고 제한된 테스트로 검증한다 | 변경 확인, 승인, 테스트 실행 대상 |
| R05 | 권한 없는 경로·승인 없는 변경을 막는다 | 승인 단위, 거절·취소 시 동작 |
| R06 | 실행 기록과 세션을 구분하고 이어갈 범위를 설명한다 | 저장 항목, 재시작 후 복원 여부, 민감정보 제외 |
| R07 | 모델 제공자와 제품 내부 계약을 분리한다 | 첫 제공자·모델, 도구 호출 지원과 변환 |

## 학생의 선택
D02 플랫폼: OPEN — CLI / 로컬 웹 / 다른 제안. 화면이 실행되는 곳과 도구를 실행하는 컴퓨터를 구분한다.
D03 언어: OPEN — Python / Node.js(TypeScript) / Rust / 다른 제안. 선택 이유를 기록한다.
D04 첫 provider: OPEN — 제공된 OpenAI API 키 / Ollama의 로컬 모델 등. 실제 모델과 도구 호출 지원 여부는 구현 시 확인한다.
D05 첫 작업과 도구 범위: OPEN — 먼저 읽기 한 작업, 이후 쓰기와 테스트. 접근할 실습 폴더와 허용할 실행을 정한다.
D06 승인 방식: OPEN — 무엇을 보여 주고 어떤 행동에 대해 받는 승인인지 정한다.
D07 세션과 저장: OPEN — 첫 버전에서 메모리만 유지할지 파일로 저장할지, 재개 의미와 한계를 정한다.
D08 추가 provider: OPEN — 전환/비교 기능을 넣을지 나중으로 미룰지 정한다.
D09 확장 기능: OPEN — 취소, 진행 이벤트, 동시 실행, 원격 접속 등에서 필요한 것을 선택하거나 미룬다.

## 완료 기준
ACCEPTANCE.md의 공통 시나리오에 실제 증거를 남긴다. 실제 모델 한 종류에서 범용 작업과 코딩 작업을 확인하고, 오류·거절도 검증한다. 추가 provider와 저장 재개는 선택한 범위에 따라 확인하거나 제외 사유를 쓴다. 모델 응답의 품질과 프로그램의 도구 실행 성공은 별개로 평가한다.
